# 通用采集目录自动建房链路

时间：2026-10-17，Asia/Shanghai。

## 使用

Web：http://127.0.0.1:5173/ 。左侧“导入房间”选择 App 输出目录，或者点击 ZIP 图标导入导出包。现在无需再点击“重建扫描家具”，导入成功后自动处理。

也可从仓库根目录指定任意 App 输出路径：

```powershell
.\env\backend\Scripts\python.exe src/backend/scripts/import-scan.py "D:\任意位置\App输出文件夹" --wait
```

不加 `--wait` 时，提交后即可返回，后台继续工作。`--structure-only` 可用于只导入结构与涂装、不启动新的图生 3D 任务。目录可以有一层或多层外包装，但只能包含一个采集包的 manifest.json。

## 自动流程

1. 根据 manifest、scene、cameras 读取本次扫描，验证完成状态、扫描 ID、米制单位、右手 Y-up 坐标、column-major 矩阵及资源路径。只发送必需 JSON、RGB 图片、家具裁剪和深度数据，不上传 USDZ、逐帧索引副本或无关文件。
2. 立即展示房间结构，按每份数据的原始墙顶计算最低高度生成天花板；不使用房间名称或固定尺寸。墙地面主色在后台恢复并缓存。
3. 读取可靠的指南针记录；磁北沿用 WMM2025 修正为真北，供太阳轨迹使用。没有可靠朝向时显示“北向待校准”，使用场景默认北向；新房间不会沿用上个房间的手动北向或经纬度。
4. 对每件家具重新选择图片。除 App 提供的裁剪图，还根据原始相机内外参从全部关键帧投影寻找候选，最多精查 12 个视角；这一步不依赖扫描文件夹名。
5. 有深度时将深度像素还原到扫描世界坐标，以目标 OBB 保留目标体积、排除相邻家具 OBB 和墙地面附近的像素，再与已有透明分割图组合。使用 OpenCV 连通域检查，保留主要目标区域，并检查完整度、遮挡、相邻家具投影重叠和截断比例。
6. 可靠单件图自动送 Rodin。生成、轮询、下载、带纹理 GLB 尺度校准和编辑低模制作沿用原链路。长/高/深来自扫描的米制尺寸，后端转换成对应毫米输入；完成后按扫描位姿自动回填。Edit 低模、Play 完整模型的选择保留。
7. UI 显示上传百分比、预处理阶段、完成数量、北向状态及逐件失败原因。个别对象待补拍或生成失败不阻塞其他对象，已有结构和尺寸代理仍可使用。

## 数据复用与任务恢复

- 导入身份由 scanId 和重建所需内容指纹确定，目录改名、换个位置、目录与 ZIP 互换都复用既有场景和任务。
- 同一 scanId 若内容不同，返回 409 并要求完整的新扫描，避免把不同几何与旧模型静默混用。
- 同时重复上传通过导入锁串行确认身份；同一场景的预处理任务只运行一份。
- 每个家具任务使用稳定请求 ID。即使服务中断发生在“任务已持久化、场景还没记住任务 ID”之间，恢复后也读取原任务，不重复创建。
- 后台预处理状态保存在 tmp，服务启动会恢复未结束的自动流程。Rodin 已受理的任务沿用原任务标识继续查询。
- 失败的付费生成不会因刷新、重新导入而自动重新计费；需要明确点击失败项的重试。
- `/api/scans/demo` 保留为兼容快捷入口，现在只重新载入最近导入的房间，不再按具体样例目录查找或特殊适配。

## 分割能力的实际边界

不能保证任意房屋、任意遮挡、任意拍摄角度都做到物品分割零错误。LiDAR 分辨率、反光表面、细腿、重叠 OBB、扫描期间家具移动都会影响判断。当前算法是几何与深度辅助过滤，不是具备完整语义理解的万能分割模型；它也可能保守地拒绝本来能由生成模型猜出的视角，仍可能残留在目标 OBB 内的小物件。

缺少深度时，仅允许标定齐全、几乎完整且与其他家具基本不重叠的原裁剪作为回退。缺少可靠候选、深度缺损或截断较严重时，不自动提交该家具，标记 `needs_review`，提示补拍独立视角。这些限制适用于所有输入，未按某间房的家具 ID 调阈值。

对现有 WallResult 单独跑选图实验时，4 件得到可用几何过滤图，3 件被保守拦截为待补拍；诊断拼图保存在 `tmp/crop-experiments/ScanDemoWallResult/comparison.png`。已有的 7 件完成模型继续复用，本次没有为验证流程重新付费生成它们。不能把现有 7/7 模型复用成功说成新分割对这份数据 7/7 全通过。
