# 多房间选择与扫描目录缓存

时间：2026-10-17，Asia/Shanghai。

## 如何加载这批房间

访问 http://127.0.0.1:5173/ ，刷新后在左侧房间下拉框选择一项即可。它读取 `reference/ToCodex/room/`，已识别 11 份采集，其中 10 份 complete、1 份 failed；失败的那份禁用，避免把未完成扫描当成可重建数据。

选择一间才启动该房间的自动流程，不会把列表中所有房间一起提交到 Rodin。第一次选择未生成过的房间，会处理结构、涂装与家具；再次选择同一套采集会复用缓存。若使用文件夹选择器，则应选包含 manifest.json 的单个 App 输出目录，不要把整个 room 父目录当成一套采集上传。

后端默认目录可通过 `ROOMCANVAS_LIBRARY_DIR` 指向其他本机目录。后端只接受列表中受限目录的 ID，不提供任意服务器路径读写接口。

## 缓存位置和内容

通过本机房间列表加载后，后端自动写回原采集目录：

```text
房间输出目录/
  manifest.json
  scene.json
  cameras.json
  ...原始采集文件...
  .roomcanvas-cache/
    cache.json
    models/
      <内容 SHA-256>.glb
```

保存完整带纹理 GLB、编辑低模、墙地面代表色与逐件处理状态。生成完成后后台会继续更新缓存，无需一直停在该房间页面。原始扫描文件不改写；派生结构、最低墙顶天花板与朝向仍从原协议适配。

缓存目录已加入 `.gitignore`。缓存中没有 Rodin API 密钥、subscription_key、任务顶层 task_uuid 或原始错误响应，仅记录公开本地任务 ID、受控状态和模型文件。

同一采集以扫描 UUID 和原始内容指纹确认身份，改目录名、换位置或重新上传不因此重建。模型载入会核对内容 SHA-256、GLB 格式与内嵌纹理，完整缓存可在清空运行时 tmp 后恢复。不同 scanId 的重新扫描视为新采集，不会把不同坐标或尺寸的家具强行套用为同一缓存。

缓存与采集内容不匹配、索引不完整、模型损坏或丢失时，停止对应对象的自动生成并提示检查，不会默默重新计费。原服务仍保留任务记录时可继续原任务；如果运行时记录已丢失、缓存又只记录了进行中的付费任务，则提示人工核对，不能凭公开本地 ID 在另一台机器恢复 Rodin 的订阅凭据。完整已完成模型不受此限制。

## 其他导入方式

浏览器的普通文件选择器只有读权限，无法静默写回任意被选目录。自动写回适用于上述本机房间列表；对其他目录可使用命令：

```powershell
.\env\backend\Scripts\python.exe src/backend/scripts/import-scan.py "D:\任意位置\App输出目录" --wait
```

`--wait` 会在完成进度变化时把模型缓存写到这个原目录。再次运行会上传并优先读取其中的缓存。普通 Web 文件夹导入也会带上已有 `.roomcanvas-cache`；“导出房间缓存”按钮提供包含该目录的 ZIP，可用于迁移。原始采集数据仍限制 300 MB，附加模型缓存限制 2 GB。
