# 墙纸与贴图加载排查及修复

## 排查结果

- 检查时 8000 后端正常，但 5173 前端开发服务已停止监听；已重新以隐藏后台进程启动。服务中断会使已打开页面无法继续加载图片。
- 500 张涂装原图及检查时 147 张缓存 JPEG 均通过 Pillow 文件验证，没有发现损坏文件。
- 7 张墙纸的缩略图和完整贴图，经后端直连及恢复后的 5173 Web 代理均返回 200，内容类型为 image/jpeg，图片可解码。
- 另发现两处前端缺陷：跨资源类别沿用搜索词可能使墙面列表为空；场景纹理失败 Promise 被保留，重选同一 URL 无法触发重新加载。

## 修改

- 分类切换清空旧搜索词；资源库提供刷新按钮，网络恢复时重新请求列表。
- 每页最多 24 张缩略图直接加载，明确图像尺寸与卡片布局，图片失败自动重试一次，仍失败则显示状态占位。刷新资源库可重新请求图片。
- 预览和场景共用 Three.js TextureLoader 加载通路，避免分别请求、解码同一贴图。
- 完整贴图每次请求设置 15 秒等待上限，失败后重试一次；最终失败移除失败缓存，重选同一贴图可恢复。
- 用版本标记触发同 URL 的重新应用，保留墙段共享图像源及原有材质比例控制；空闲图像缓存限为两张。
- 加载失败时场景保留扫描涂装，未修改扫描原始数据、家具生成或手机上传链路。

## 验证

- `npm run build` 通过；已有包体积提示，无编译错误。
- `npm run verify:finishes` 通过，新增模拟两次请求失败后，同 URL 重选恢复、预览与墙段复用同一图像源的回归检查。
- `env/backend/Scripts/python.exe src/backend/scripts/verify-catalog.py` 通过，新增全部 7 张墙纸缩略图及完整贴图解码验证。
- Web 首页、资源组件和墙纸资源 API 正常响应，开发服务器保持运行。
- 当前浏览器连接仍不可用，未进行真实浏览器截图或 GPU 像素验收。
