# 墙体渐变终点闪变修复

## 原因与修改

旧实现用 `opacity < 1` 决定材质 `transparent` 与 `depthWrite`。透明度恢复至 1 的最后一帧，会从透明队列切换到不透明队列，同时开启深度写入并标记材质更新。Three.js 对两种队列分别排序和绘制，且 shader 参数包含 opaque 标志，因此透明度的连续变化无法保证这一帧的遮挡合成也连续。

Edit 模式现在始终保持 `transparent=true`、`depthWrite=false`，包括透明度为 1 的实墙。动画只修改 opacity，终点不再切换队列、深度设置或使材质重新更新。渲染设置仅在模式切换时调整；Play 立即取消渐变，恢复 `opacity=1`、不透明渲染和深度写入。

保留 0.5s Cubic.Out 渐变、途中从当前透明度反向过渡、静止后继续完成，以及减少动态效果设置下的 0.2s 过渡。原有有限射线与凹角遮挡判定不变。
