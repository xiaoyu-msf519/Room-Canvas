# L 型房间凹角墙遮挡补充

## 问题与实现

用户截图中的 L 型边界形成三段折线。只判断相机位于墙的内侧或外侧，会漏掉中间那段墙：相机虽然处于它的室内半空间，该墙依然可能挡住另一侧房间和家具。

- 保留上一阶段 Blueprint3D 的近墙淡化，补充从相机到室内采样点及家具采样点的有限线段检测。
- 室内目标来自真实多边形地板内的自适应网格、三角形中心和两组高度，覆盖狭窄侧翼；家具取中心及上部四角，更新家具位置后重新判断。
- 用墙板预计算的逆矩阵，将有限线段转换到墙局部坐标，调用 Three.js Ray.intersectBox 检测。检测只覆盖 30 块墙板包围盒，不遍历高模三角面。
- 同一线段上的多个遮挡墙都可以淡化，因此 S 型折线的三段不再只处理第一段。
- 必须在相机与室内目标之间命中，目标之后的墙不参与；落在墙内/边缘的目标排除，避免重新出现无限射线导致所有墙半透明的问题。
- 仍采用标准 MeshStandardMaterial，淡化墙不写深度；Play 全部墙恢复不透明和深度写入。
- 相机和家具引用未变时复用结果，扫描轮询未改变几何时复用墙板资源。

## 验证

- `npm run verify:walls`：新增 L 型房间 S 形三段边界，先断言法线判断确实会漏掉中间墙，再断言三段有限线段均命中、三墙同时淡化，后方远墙保持实心。覆盖旋转 OBB、目标位于墙内、Play 还原及实际 ScannedRoom 组件。
- 真实扫描四个外部视角仍同时存在实心/半透明墙：18/12、14/16、13/17、19/11，没有全部墙透明。
- `npm run verify:scan` 和 `npm run build` 通过，保留原有主包体积提示。
- 本机 Node 下真实扫描、移动相机的 70 次热运行：遮挡更新中位数 0.537ms，P95 0.917ms；静止视角 1000 次缓存更新合计 0.322ms。这些是 CPU 检测开销，不代表浏览器 GPU 帧率。
- 前后端服务继续运行于 `http://127.0.0.1:5173/` 和 `http://127.0.0.1:8000/`。
