# 视角移动性能优化

## 发现的开销

- Edit 模式即使墙面完全不透明，也通过 BSP 细分碎片渲染。当前房间有 34 个墙段、424 个 BSP 面组，增加了透明排序和绘制开销。
- 漫游时像素采样最高 2x，像素量是 1x 的四倍；持续转动视角仍使用这一采样量。
- 光照动画或家具拖动会频繁重画全场阴影。
- 家具实例重复创建相同材质；扫描轮询返回相同数据时仍替换场景引用，触发组件更新和资源检查。

## 修改

- 完全不透明的 Edit 墙体改走普通深度绘制，每墙一组；处于透明或渐变阶段的墙继续使用原 BSP 排序与 0.5s 渐变。
- 独立维护不透明和透明材质，在同一帧切换可见性；涂装、选中效果、米制 UV 同步到两种材质，不在过渡端点修改透明材质的深度写入规则。
- OrbitControls 使用现有 R3F 性能回退机制；Play 移动或环视时也进入回退。移动时像素采样为正常值的 70%，对应约 49% 的像素量，停止 250ms 后恢复。Canvas 保持常驻，模型仍为 Edit 低模、Play 高模。
- 太阳位置、颜色和强度仍逐帧更新；连续光照动画与家具拖动的阴影刷新限制到 20Hz，场景内容变化立即刷新。
- 相同 GLB 的实例共享不可变几何、材质和纹理，模型包围尺寸按源对象缓存，保留原位姿、中心和真实尺度校准。
- 家具组件只订阅自己的选中状态，使用 memo；相同扫描轮询不更新状态，元数据变化时复用未改变的房间和家具引用。
- Play 已进入实墙状态后跳过无意义的墙体遮挡重算；缓存每个墙段的相机局部坐标。

## 验证

- `npm run verify:performance`：实际 R3F 组件在观察位置 `[8,7,8]`，墙体颜色绘制可见组由 424 降为 225，约减少 47%；检查完整一圈视角中的透明/不透明交接、轮询引用复用、模型资源共享、分辨率降低与恢复。
- 同房间模拟 100 件家具、600 次相机位置更新，墙体分类约 0.93ms/次。此数据仅为当前环境的一次 CPU 基准，不代表 GPU 帧率。
- `npm run verify:walls`：BSP 深度顺序、30/60/120fps 渐变、L/S 边界、Play 实墙和材质复用通过。
- `npm run verify:finishes`：墙纸/地板、共享纹理及断线恢复通过。
- `npm run verify:solar`：太阳表格、Worker、方向、平滑光照、阴影复用和日夜变化通过。
- `npm run verify:scan`：扫描墙地面、天花板、漫游碰撞及模型替换时编辑状态通过。
- `npm run build` 通过；已有包体积提示，无编译错误。
- Web 及新增组件通过 5173 服务正常读取，服务保持运行。

## 限制

- 当前浏览器连接不可用，尚未进行真实浏览器 FPS、GPU 时间和画面截图验收；绘制组计数来自实际 R3F 场景组件，未声称 GPU 帧率提升比例。
- 本阶段没有调整鼠标灵敏度、家具编辑坐标逻辑或生成接口；未执行付费生成任务。
