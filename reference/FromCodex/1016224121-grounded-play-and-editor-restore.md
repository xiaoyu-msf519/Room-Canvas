# 地面漫游、编辑视角恢复与滚轮缩放

## 交付行为

- Play 相机始终固定在平地上方 1.7m；WASD / 方向键只沿当前朝向在 XZ 平面移动，抬头不会向上飞，俯视也不会钻入地面。
- 从 Edit 进入 Play 时，先保存编辑相机的位置、四元数朝向、Orbit 观察目标、FOV 和 zoom，再从房间原点 `(0, 1.7, 0)` 水平朝向开始漫游。
- 出生点有占用时，以 0.25m 步长向外搜索附近空位。检测玩家身体体积与旋转后的家具、墙体 OBB；没有合法位置则取消进入，不强行出生到障碍物中。
- Esc、停止按钮或 Pointer Lock 解锁时恢复进入前的编辑相机和观察目标。切换在渲染前完成，清空残留输入；关闭 Orbit 阻尼避免恢复后被旧惯性带走。
- Edit 滚轮由 OrbitControls 拉近/拉远相机，距离限制 0.25–80m；Play 滚轮改变 FOV，限制 30–85 度，眼高始终保持 1.7m。退出 Play 后恢复原编辑倍率。
- 行走检测家具与墙体碰撞框并保留原有水平边界；对过长帧限制移动步长。

## 数据与实现边界

`types/scene.ts` 新增 SceneCollider，家具复用该位姿与尺寸契约；SceneManifest.room 预留 colliders，状态新增空的 roomColliders。当前没有真实房间数据，仍以 Y=0 平地和世界原点为基准；未来扫描适配器需将房间墙体 OBB 写入 roomColliders、家具写入 furnitureList，才能对真实房间生效。本阶段未实现坡面、楼梯或多层地形。

- `npm run build` 通过，TypeScript / Vite 零错误；保留原有 Three.js 包体积警告。
- 使用 Three.js 与实际 OrbitControls 完成针对性断言：1.7m 原点出生、占用偏移、旋转墙体、无可用出生点、边界、编辑缩放、Play FOV 限制与投影更新、缩放不改变高度、连续五轮相机恢复。
- 本地入口与更新后的相机模块均返回 HTTP 200：`http://127.0.0.1:5173/`。
