# 按视线与室内体积求交的墙体透视

## 最终规则

按本轮用户明确的判定：以相机为起点、朝墙面每一点发射正向射线，只要射线任意一段经过室内，该墙面点就半透明。室内可以位于当前墙面之前，也可以在其后，因此同一条视线上的近墙和远墙都可能半透明。相机位于室内时，Edit 模式射线同样命中室内。

Play 模式始终保持墙体完全实心，不启用透视。

## 实现

- 新增 `src/frontend/src/scene/wallVisibility.ts`，将真实地板多边形三角化，沿房间高度形成三棱柱的并集，支持凹形地板轮廓。
- 每个墙面片元用相机世界坐标和片元世界坐标生成射线，在 GPU 上做解析半空间裁剪求交。不使用整块墙统一透明，也不只用房间包围矩形或墙前后两个采样点判断。
- 判定使用从地面到墙顶的真实高度，排除从天花板上方、地板下方掠过或只有相机背后才有室内的射线。
- 室内相交部分不透明度为 0.18；不相交部分保持不透明。
- 分为不透明深度通道和半透明叠加通道：透视部分不写深度，避免虽然半透明却仍遮住家具；实心部分正常写深度。
- Play 关闭求交开关并移除半透明通道，材质不透明度为 1。已有墙体/家具碰撞与模型重建逻辑不变。
- 材质在所有墙板间共享，场景轮询返回相同几何时继续复用，避免重复分配 GPU 资源。

## 验证

- `npm run verify:walls` 通过：近墙、远墙、室内相机、逐点不同结果、凹形缺口、上下高度、反向射线、空数据、Edit/Play 切换、深度写入与材质复用。
- `npm run verify:scan` 通过：实际扫描的 30 块墙板、多边形地面、碰撞与模型状态同步回归。
- `npm run build` 通过，保留现有主包体积提示。
- 前端与后端代理健康检查均返回 HTTP 200，后台服务继续运行：`http://127.0.0.1:5173/`。
- 内置浏览器实例列表为空，未完成 GPU 实际绘制截图或真实浏览器视觉验收。组件测试核对材质 shader 注入与状态切换，不能代替实际 GPU 图像检查。
